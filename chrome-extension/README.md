# X Remarks — Chrome 扩展版

和 `x-remarks.user.js`(iOS Safari / Userscripts)同样的功能:在 X(Twitter)的用户名下面显示本地备注,点一下药丸就能改。这一版是标准的 Chrome MV3 扩展。

## 安装

1. 打开 `chrome://extensions/`
2. 右上角打开「开发者模式」
3. 点「加载已解压的扩展程序」,选中 **本文件夹**(`chrome-extension/`)
4. 打开 https://x.com,首次安装会自动种入内置的 155 条备注

Edge / Brave / Arc 等 Chromium 内核浏览器同样适用。

## 用法

- **时间线**:有备注的用户,名字下面独占一行显示蓝色药丸;点药丸弹出编辑框(保存 / 删除 / 取消,回车保存,Esc 取消)
- **个人主页**:有备注显示药丸,没有备注显示「＋ 备注」
- **用户列表**:关注/粉丝列表、"你可能感兴趣"侧栏、搜索的用户 tab、转发者列表(`UserCell`)也显示药丸,弹层里的列表同样覆盖
- **降噪**:命中「降噪」规则的作者(默认是拉黑那一类),整条推文按设置处理 —— 淡化 / 折叠 / 隐藏
- **去广告**:信息流推广推文 + 推广趋势,默认开

工具栏图标点开是管理面板,三个 tab:

**备注** —— 打开就聚焦搜索框,按 handle 或备注内容过滤,右上角显示「命中 / 总数」。点备注文字就地改,点 handle 在新标签打开主页,点 `✕` 删除。`分组` 按备注文案聚合并按人数排序,用来发现该合并的标签("避而远之" 到底标了多少人)。`＋ 添加` 展开手动新增行(`@handle` 支持粘贴完整主页链接,会自动截成 handle)。

> 删除是**两步**的:第一下只是把 `✕` 变成红色的「删除?」,数据还没动,3 秒不点自己退回去;再点一次才真删,而且 toast 里还有「撤销」。手攒的数据,误点一次不该丢。

**规则** —— 关键词 → 颜色 + 是否降噪。**从上往下匹配,第一条命中的生效**,所以拉黑类要放最前面,`↑` `↓` 调顺序。颜色点开是 X 那套预设色板(末尾还有自定义)。右边的命中人数**可以点** —— 跳到备注 tab 只看这一类人。默认三条:

| 规则 | 关键词 | 颜色 | 降噪 |
|---|---|---|---|
| 拉黑 | 避而远之 / 割人 / 骗子 / 诈骗 / 反指 / 大割 / 畜生 / 小心 | 红 | ✅ |
| 项目方 | 创始人 / CEO / 项目方 / 台子 / 合伙人 / dev / 开发 | 灰 | — |
| 投研 | 投研 / 研究 / 分析 / alpha / kol / 交易 | 绿 | — |

按内置的 155 条备注跑下来,命中分布是 拉黑 27 / 项目方 28 / 投研 38,其余 62 条不命中任何规则,走主题默认蓝。

**设置** ——

- **降噪方式**:`关闭`(只标颜色)/ `淡化`(变灰变淡,鼠标移上去恢复,程度可调,默认 30%)/ `折叠`(收成一行"@handle · 备注 · 展开",点一下展开)/ `隐藏`(整条不显示)。默认 `淡化`。
- **隐藏推广内容**:信息流广告 + 推广趋势。
- **备份**:导入文件 / JSON 保存 / 回滚前自动存档,保留最近 3 份,随时一键回滚 —— 手攒的数据,粘错一次不至于全没。
- 导出 / 导入文件、复制 JSON、`编辑 JSON` 整体编辑。

所有改动在打开的 X 标签页里即时生效,不需要刷新。

## 配色

统一用 X 的品牌蓝 `#1d9bf0`(不是 iOS 蓝)—— 药丸贴在 X 界面里,用另一种蓝会跟 X 自己的链接色打架。规则色板也是 X 那套强调色:红 `#f4212e` / 橙 `#ff7a00` / 黄 `#ffd400` / 绿 `#00ba7c` / 蓝 `#1d9bf0` / 紫 `#7856ff` / 粉 `#f91880` / 灰 `#71767b`。

弹窗的深浅色**跟 X 走,不跟系统走**:`content.js` 把当前主题写进 `x_remarks_theme`,弹窗读它。否则你在系统浅色下用 X 的暗色模式时,页面弹窗是黑的、工具栏弹窗是白的。

## 与 Safari userscript 版的差异

| | userscript(iOS) | Chrome 扩展 |
|---|---|---|
| 存储 | `localStorage`,清站点数据会丢 | `chrome.storage.local`,清网站数据不受影响 |
| 设置入口 | 页面右下角悬浮 ⚙ 按钮 | 浏览器工具栏图标弹窗 |
| 备注管理 | 只有一个 JSON 文本框 | 列表 + 搜索 + 就地编辑,外加 JSON 视图 |
| 导入导出 | 复制粘贴 | 文件导入导出 + 复制 |
| 内置数据 | 内嵌在脚本里,首次运行种入 | `defaults.js`,`onInstalled` 时种入,**升级扩展不覆盖已有数据** |

数据结构完全一致,两边的 JSON 可以直接互相导入。

## 数据格式

```jsonc
{
  "@elonmusk": "马斯克",
  // 单条可以用对象形式覆盖样式
  "@someone": { "note": "备注", "color": "#f4212e", "fontSize": "13px", "borderRadius": "10px" },
  // 设置和规则(userscript 版读不懂,但导入导出会原样保留,不会丢)
  "__settings": {
    "noiseMode": "dim",
    "dimOpacity": 0.3,
    "hideAds": true,
    "rules": [
      { "name": "拉黑", "color": "#f4212e", "noise": true, "match": ["避而远之", "割人"] }
    ]
  },
  // 全局样式
  "__style_bgColor": "#1d9bf0",
  "__style_fontSize": "12px",
  "__style_borderRadius": "6px"
}
```

- key 保留 `@` 前缀;查找大小写不敏感,写入保留原始大小写
- 药丸颜色优先级:**单条 `color` > 规则 `color` > `__style_bgColor` > `var(--xr-accent)` 跟随主题**
- 规则匹配是子串、大小写不敏感,第一条命中即停;`rules.js` 是内容脚本和弹窗共用的同一份实现,所以"页面上什么颜色"和"弹窗里命中几人"永远一致

## 文件结构

| 文件 | 职责 |
|---|---|
| `manifest.json` | MV3 清单,只申请 `storage` 权限 + x.com/twitter.com 主机权限 |
| `defaults.js` | 内置备注数据 + 默认设置/规则,content script 和 service worker 共用 |
| `rules.js` | 规则匹配,内容脚本和弹窗共用同一份实现 |
| `background.js` | 仅在首次安装时把内置数据和默认设置写进 storage |
| `content.js` | 页面注入:识别用户、插徽章、降噪、去广告、编辑弹窗、主题跟随 |
| `content.css` | 徽章 / 降噪 / 折叠条 / 弹窗 / toast 样式,主题变量由 `content.js` 写到 `:root` |
| `popup.html/css/js` | 工具栏面板:备注 / 规则 / 设置三个 tab |

## 改代码前必读(踩过的坑,别重犯)

1. **事件委托挂 `window`,不是 `document`**。X 的脚本先加载,它在 document 上的监听排在前面,一旦 `stopImmediatePropagation` 就收不到事件。症状:一开始能点,SPA 路由切换后突然失效。
2. **不要在 `pointerdown` / `touchstart` 上 `preventDefault()`**,只 `stopPropagation()`。拦 X 的「点推文进详情」用后者就够。
3. **不要给徽章单独 `addEventListener` 当唯一通路**。React 换掉节点后监听就没了 —— 委托是主通路,元素级绑定只是兜底。
4. **不要往用户名那一行插元素**。那是定宽 flex 行,会把名字挤成省略号。`findColumnSlot` 向上找纵向容器,让徽章独占一行。
5. **不要依赖 X 的 class 名**(混淆且常变)。只用 `data-testid`:时间线 `User-Name`,个人主页 `UserName`(注意有无连字符),用户列表 `UserCell`。
6. **扫描根用 `document`,不是 `main`**。关注/粉丝/转发者列表是 `div[role="dialog"]` 弹层,在 main 外面,只扫 main 会漏。
7. **虚拟列表会复用节点**,同一个区块可能换成别的用户。靠 `badgeOwner` WeakMap 精确清理旧徽章,否则会串号。
8. **取 handle 优先读链接 href,别扫 span**。扫 span 取最后一个 `@` 开头的文本,遇到"显示名里写了 @xxx"的用户会挂到错误的 handle 上;而且每个区块遍历全部 span 在滚动时很贵。`handleFromHref` 带一份一级路径保留字表(`/home`、`/i/...` 之类不是用户名)。个人主页的 handle 可能不是链接,所以扫 span 只作兜底。
9. **防抖必须带上限**(`IDLE_WAIT` 250ms / `MAX_WAIT` 800ms)。纯 trailing 防抖会被饿死:自动播放的视频、"显示 N 条新帖"计数器、加载骨架屏都在持续吐 mutation,定时器一直被推后,`renderAll` 永远不执行 —— 症状是"滚半天不出药丸,随手点一下又好了"。
10. **`getComputedStyle` 别放在滚动热路径**。`findColumnSlot` 按场景(`timeline` / `usercell`)缓存"向上爬几层",命中后只校验一次,结构变了自动作废重扫。
11. **编辑弹窗要拦 `keydown/keyup/keypress`**。X 有一堆单键快捷键(j/k/n/l…),不拦的话打字会触发它们。
12. 扩展重新加载后,旧标签页的 content script 会 context invalidated;`persist()` 已经接住同步抛错和异步 reject,提示刷新页面。
13. **降噪一律作用在 `article` 上,不要碰外层 `cellInnerDiv`**。X 的虚拟列表用绝对定位摆放每个 cell,直接隐藏 cell 会留下一个空洞;让 article 塌成 0 高度,X 自己的 ResizeObserver 会把位置重排,空隙自然合上。广告也是同理 —— 只收 `placementTracking` 这一层。
14. **降噪只认作者的 User-Name**(`article` 里的第一个)。引用推文里也有 User-Name,不加这个判断,被引用的人上了黑名单就会把整条推文折叠掉。
15. **`decorate()` 里 `noteObj` 为空也要跑 `applyNoise`**,否则虚拟列表回收复用的节点会留着上一位的降噪状态;再加 `sweepNoise()` 兜住"article 被回收成压根没有 User-Name 的模块"这种情况。
16. **主题 key `x_remarks_theme` 单独存,不要塞进 `STORAGE_KEY`**。导出的 JSON 必须保持"只有 `@handle` / `__` 开头保留键"这个结构,和 userscript 版互导才不会带脏数据。
17. **弹窗里改一行不要整表重绘**。155 条全量 `render()` 会把滚动位置弹回顶部,改到一半的人得重新找。就地编辑和单条删除都走 DOM 手术(`li.remove()` / 改 `textContent`),只有分组归属变了才整表重排。
18. **`tabs button.on` 在暗色下必须比底槽更亮**。分段控件的语义是"选中项浮起来",暗色下如果选中态比容器更暗,看着就像没选中。`--seg-bg` / `--seg-on` 两个变量分开定义就是为了这个。
19. **弹窗的 `:root[data-theme]` 要能压过 `@media (prefers-color-scheme)`**。前者特异度 (0,2,0)、后者 (0,1,0),两个方向都压得住,所以不依赖书写顺序。
